## 1. はじめに / この文書について

この文書は、これから作る「**スマホ（iPhone）でアイコンをタップすると Windows PC で対応する操作が実行される**」アプリ（Stream Deck 風アプリ）の **要件定義書** です。

- **要件定義書とは**：「何を・なぜ・どこまで作るか」を最初に言葉にしておくメモです。作り方（コードの詳細）ではなく、**ゴールと範囲**を決めるものです。
- **読み方**：上から順に読めば、「なぜ作るか → 何を作るか → どう動くか → 何を学ぶか → リスク → 進め方」が分かるように並べています。専門用語は **4. 用語集** に先にまとめています。
- **この文書は「生きた文書」です**：アジャイル開発で進めるため、作りながら気づいたことを反映して**何度でも更新**します。最初から完璧でなくて構いません。

## 2. 背景・課題

配信や日々の作業で使う「ボタン1つで操作を実行する」デバイス／アプリ（いわゆる Stream Deck）が欲しい。しかし既存のアプリには次の不満がある。

- **サブスク前提**で、使い続けるのにお金がかかる／機能が制限される。
- **UI/UX が良くない**。特に**画面に並ぶアイコンの質が低い**（ぼやける・ダサい・カスタマイズしづらい）。

そこで、**自分の環境（Windows PC ＋ iPhone）に合った、見た目がきれいで自由にカスタマイズできるものを自作する**。あわせて、アプリ開発の学習も目的とする。

---

## 3. 目的・ゴール / 非ゴール

### ゴール（このプロジェクトで実現したいこと）
- iPhone のボタンをタップすると、Windows PC 側で以下が実行できる：**①アプリ起動 ②URL/サイトを開く ③キーボードショートカット送信 ④音量・メディア操作**。
- **高品質で自由にカスタマイズできるアイコン／UI**（既存アプリへの最大の不満を解消する）。
- **サブスク不要**（自分のPCで動く・無料）。
- **アプリ開発の基礎を学ぶ**（Web・サーバー・通信の仕組みを手を動かして理解する）。

### 非ゴール（今回は“やらない”こと。線引きを明確にする）
- 公開・配布（まずは自分専用。将来の拡張余地は残す）。
- 外出先からインターネット経由で操作すること（**LAN内のみ**）。
- 複数人での同時利用・アカウント管理。
- ネイティブ iOS アプリ（App Store 配布）。→ **PWA** で実現する。
- プッシュ通知。

## 4. 用語集

初めての人向けに、本書に出てくる言葉を先にまとめます。

| 用語 | かんたんな説明 |
| --- | --- |
| **PWA**（Progressive Web App） | Webサイトを「ホーム画面に追加」してアプリのように使える仕組み。App Store 不要・Mac 不要で作れる。今回スマホ側はこれ。 |
| **サーバー / クライアント** | サーバー＝命令を受けて処理する側（今回は Windows PC）。クライアント＝命令を出す側（今回は iPhone）。 |
| **LAN** | 家の中の同じ Wi-Fi で繋がったネットワーク。今回はこの中だけで通信する。 |
| **IPアドレス** | ネットワーク上の住所。例 `192.168.1.42`。PCの住所をスマホに教えてアクセスする。 |
| **ポート** | 1台のPCの中の「窓口番号」。例 `:3000`。アプリごとに番号を使い分ける。 |
| **HTTP / REST** | Webでデータをやり取りする基本ルール。「このボタンを押した」を送るのに使う。 |
| **API / エンドポイント** | プログラム同士の窓口。例 `POST /api/press`＝「ボタンが押された」を伝える窓口。 |
| **WebSocket** | サーバーとスマホが繋ぎっぱなしで双方向に通信できる仕組み。状態表示などで後から使う。 |
| **Node.js** | PC上で JavaScript を動かす実行環境。今回のPC側サーバーをこれで作る。 |
| **npm / パッケージ** | Node.js の部品（ライブラリ）を入れる仕組み。`npm install ◯◯` で導入する。 |
| **child_process** | Node.js から別のプログラム（アプリ）を起動するための標準機能。 |
| **ホットキー / ショートカット** | `Ctrl+C` のようなキー操作。PCに送って実行させる。 |
| **許可リスト（allowlist）** | 「これだけは実行してよい」と事前に決めたリスト。安全のため、登録外の命令は実行しない。 |
| **service worker** | PWAをオフラインでも動かす裏方。**HTTPSが必要**な点に注意（後述）。 |
| **mDNS（.local）** | IPアドレスの代わりに `streamdeck.local` のような名前でアクセスする仕組み。将来の便利機能。 |
| **ファイアウォール** | 通信を許可/拒否する番人。初回にPCで「許可」を押す必要がある。 |

## 5. 対象ユーザー / 想定利用シーン

- **対象ユーザー**：自分ひとり（Windows PC と iPhone を持ち、同じ Wi-Fi 内で使う）。
- **想定シーン**：
  - 作業開始時に、1タップでよく使うアプリ（Chrome、VSCode など）をまとめて起動。
  - 配信・作業中に、PCに触れず手元のiPhoneからショートカットを送信。
  - 音量を上げ下げ／再生・停止・曲送りを手元で操作。
  - よく見るサイト（管理画面・ダッシュボード等）を1タップでPCのブラウザに表示。

> MVP = Minimum Viable Product（最小限の、まず動く製品）

| 区分 | 含む（MVP） | 含まない（今回は対象外） |

| 画面 | ボタングリッド表示・タップで実行 | 状態のリアルタイム表示（現在音量など） |
| 配布 | 自分のPCで動かす | App Store / 一般配布 |

## 7. システム構成・アーキテクチャ

### 全体図

```
[iPhone] Safari / PWA（ホーム画面に追加してアプリ風に起動）
      │
      │  ① ボタンをタップ
      │  ② HTTP で「このボタンが押された」を送信（あとで WebSocket も）
      │     同じ Wi-Fi（LAN）内で、PCの住所にアクセス
      │     例: http://192.168.1.42:3000
      ▼
[Windows PC]  Node.js サーバー（常駐して待ち受ける）
      │  ③ buttons.json（許可リスト）からボタンIDに対応する操作を探す
      │  ④ 対応する操作を実行：
      ├─ child_process ……… アプリ起動 / URLを開く
      ├─ @nut-tree-fork/nut-js … キーボードショートカット送信
      └─ NirCmd / win-audio …… 音量・メディア操作
      │  ⑤ 「成功/失敗」をスマホに返す
      ▼
[Windows PC でアプリが起動・操作が実行される]
```

### データの流れ（1タップの裏側）
1. iPhone でボタンをタップ。
2. PWA が `POST /api/press`（本文に `{"buttonId":"chrome"}`）をPCへ送る。
3. サーバーが `buttons.json` を見て `chrome` に対応する操作（例：Chromeを起動）を確認。
4. 許可リストにあれば実行、なければ拒否。
5. 結果（`{ok:true}` など）をスマホに返す。

## 8. 機能要件（優先度: MoSCoW）

> Must=必須 / Should=できれば / Could=あれば嬉しい / Won't=今回はやらない

| ID | 機能 | 優先度 | 受け入れ条件（これが満たせたら完成） |
| --- | --- | --- | --- |
| F-01 | PCアプリの起動 | **Must** | スマホでボタンを押すと、登録済みのアプリ（例: Chrome）がPCで起動する |
| F-02 | URL/サイトを開く | **Must** | ボタンを押すと、指定URLがPCの既定ブラウザで開く |
| F-03 | キーボードショートカット送信 | **Must** | ボタンを押すと、指定したキー（例: Ctrl+C）がPCで実行される |
| F-04 | 音量・メディア操作 | **Must** | 音量±／ミュート／再生・停止・曲送りがボタンで動く |
| F-05 | ボタンを設定ファイルで定義 | **Must** | `buttons.json` を編集すると、表示と動作が変わる |
| F-06 | 許可リスト方式 | **Must** | `buttons.json` に無いIDは実行されず拒否される |
| F-07 | 簡易PIN/トークン認証 | Should | 正しいPIN/トークンが無いと操作できない |
| F-08 | プロファイル/ページ切替 | Should | 複数ページのボタンを切り替えて使える |
| F-09 | カスタム画像アイコンのアップロード | Should | 任意のPNG/SVGをボタンのアイコンに設定できる |
| F-10 | サーバーの自動起動（常駐） | Should | PC起動時にサーバーが自動で立ち上がる |
| F-11 | 状態のリアルタイム表示（現在音量/再生中） | Could | WebSocketでボタンに現在状態が表示される |
| F-12 | ドラッグ&ドロップでボタン編集 | Could | 画面上でボタンを並べ替え・編集できる |
| F-13 | mDNS（streamdeck.local）対応 | Could | IP固定なしで名前でアクセスできる |
| F-14 | 外出先からの操作 / 複数ユーザー / ネイティブiOS / プッシュ通知 | **Won't** | 今回は対象外（将来検討） |

## 9. 非機能要件

| 観点 | 要件 |
| --- | --- |
| **性能** | LAN内でタップから反応まで概ね 300ms 以内を目標。 |
| **アイコン品質（最重要）** | SVGアイコンセット（Lucide / Simple Icons / Tabler / Material Symbols 等）で**どの画面サイズでもぼやけない**。さらに**自分の画像を設定可能**。既存アプリへの最大の不満を解消する。 |
| **使いやすさ** | iPhone の片手操作で押しやすい**大きめのタップ領域**。ダークテーマ。iOSでの導入手順（ホーム画面に追加）を分かりやすく用意。 |
| **セキュリティ** | 許可リスト方式・LAN限定・（Should）PIN/トークン。リクエストの値を**そのままシェルに渡さない**。詳細は 17 章。 |
| **信頼性** | サーバーは常駐して待ち受ける。落ちても再起動で復帰。設定ミスでも全体が止まらない。 |
| **保守性** | 設定は **`buttons.json` の1ファイル**に集約し、コードを触らずボタンを増減できる。 |
| **iOS制約（正直に明記）** | ・PWAのインストールは**手動**（共有→「ホーム画面に追加」）。<br>・ホーム画面アイコンは **`apple-touch-icon.png`（180×180）** を使用。<br>・**service worker（オフライン化）は HTTPS が必須**。素の `http://192.168.x.x` では当面オフライン非対応（Phase 4 でHTTPS化して解禁）。<br>・**プッシュ通知は非対応**（今回は不要＝対象外）。 |

## 10. 技術スタックと選定理由

**方針：スマホ側もPC側も JavaScript に統一**。学ぶ言語を1つに絞り、学習負荷を下げる。

| 領域 | 採用技術 | 理由 | 注意点 |
| --- | --- | --- | --- |
| スマホ側UI（最初） | HTML + CSS + 素のJS | ビルド不要・最短で動く・基礎が学べる | まずは1ボタンから |
| スマホ側UI（発展） | Vite + React + vite-plugin-pwa | 高速・情報が豊富・PWA化が簡単・UIを綺麗に作れる | Phase 3 で移行 |
| PC側サーバー | Node.js + Express | フロントと同じJS／情報が多く初心者向け | 初回にファイアウォール許可が必要 |
| アプリ起動 | `child_process`（Node標準） | 追加インストール不要・依存ゼロ | アプリは**フルパス**で登録 |
| URLを開く | `open`（npm） | API が簡単（`open('https://…')`） | `start` でも代替可 |
| ショートカット送信 | **`@nut-tree-fork/nut-js`（無料フォーク）** | **プリビルドバイナリ同梱でビルドツール不要** | **公式 `@nut-tree/nut-js` は有料トークン制。`robotjs` はメンテ終了。必ずフォークを使う** |
| 音量・メディア | NirCmd（外部exe）/ 慣れたら `win-audio` | NirCmdは**コンパイル不要**で確実 | メディアキーが不安定なら NirCmd にフォールバック |
| 通信 | まず HTTP REST → 後で WebSocket（`ws`） | RESTは理解が簡単／状態表示時にWS | 段階的に発展 |
| 設定 | `buttons.json` | UIの描画元＋許可リストを兼ねる | 手編集できる形に |
| アイコン | SVGセット ＋ カスタム画像 | ぼやけない・自由 | 本プロジェクトの肝 |

> **最重要メモ**：ショートカット送信ライブラリは **`@nut-tree-fork/nut-js`**（無料フォーク）を使う。公式版は有料化されており、間違えると**課金、または `node-gyp`/Visual Studio Build Tools/Python が必要なビルド地獄**にハマる。

## 11. ユーザーストーリー

「**〜として、〜したい。なぜなら〜だから。**」の形で。

- 利用者として、**PCのIPを入力して接続したい**。なぜなら、まずスマホとPCを繋ぐ必要があるから。
- 利用者として、**1タップでよく使うアプリを起動したい**。なぜなら、作業開始を素早くしたいから。
- 利用者として、**ボタンで好きなサイトをPCで開きたい**。なぜなら、毎回URLを打つのは面倒だから。
- 利用者として、**手元からショートカットを送りたい**。なぜなら、PCに触れず操作したいから。
- 利用者として、**音量・再生を手元で操作したい**。なぜなら、離れた場所からも調整したいから。
- 利用者として、**ボタンのアイコンを綺麗な画像にしたい**。なぜなら、見た目の良さがこのアプリを作る理由だから。

## 12. 画面・UI要件

- **ボタングリッド**：列×行のグリッドにアイコン＋ラベルのボタンを並べる（例 4列×3行）。タップで実行。
- **プロファイル / ページ切替**（Should）：用途別にページを分け、上部タブやスワイプで切替。
- **設定画面**：接続先（PCのIP）・PIN・テーマなどを設定。
- **接続/PIN画面**：初回にPCのIPと（必要なら）PINを入力。
- **アイコン表示**：SVGで鮮明に。カスタム画像も表示可。
- **テーマ**：ダークテーマを基本に、押しやすい大きめボタン。

## 13. データ・設定仕様（`buttons.json`）

ボタンの見た目と動作を**1つの設定ファイル**で定義する。このファイルは **UIの描画元** であると同時に、**実行してよい操作の許可リスト**を兼ねる（＝安全の要）。

構造：**プロファイル → ページ → ボタン**。`action.type` は `launch`（起動）/ `url`（URLを開く）/ `hotkey`（ショートカット）/ `media`（音量・メディア）。

```jsonc
{
  "profiles": [
    {
      "name": "Default",
      "pages": [
        {
          "name": "Main",
          "grid": { "cols": 4, "rows": 3 },
          "buttons": [
            {
              "id": "chrome",
              "label": "Chrome",
              "icon": "simple-icons:googlechrome",
              "color": "#4285F4",
              "action": { "type": "launch", "target": "C:/Program Files/Google/Chrome/Application/chrome.exe" }
            },
            {
              "id": "copy",
              "label": "Copy",
              "icon": "lucide:copy",
              "action": { "type": "hotkey", "keys": ["LeftControl", "C"] }
            },
            {
              "id": "vol-up",
              "label": "Vol +",
              "icon": "lucide:volume-2",
              "action": { "type": "media", "command": "volumeUp" }
            },
            {
              "id": "docs",
              "label": "Docs",
              "icon": "simple-icons:readthedocs",
              "action": { "type": "url", "target": "https://example.com" }
            }
          ]
        }
      ]
    }
  ]
}
```

> **拡張しやすさ**：将来「マクロ」「OBS連携」などを足すときは、新しい `action.type` と、それに対応する処理を1つ追加するだけでよい設計にする。

## 14. 開発の進め方（アジャイル / Claudeエージェント活用）

- **アジャイル**：短いサイクルで「**まず動くものを作る → 使ってみて改善**」を繰り返す。各フェーズの終わりに必ず「動く成果物」がある状態にする（18章）。
- **Claudeエージェントの使い方**：
  - **解説役**：分からない用語・エラーの意味を聞く（学習を加速）。
  - **雛形生成**：サーバーやUIの最初のコードを作ってもらう。
  - **デバッグ**：Windows特有のエラーやネイティブビルドの問題を一緒に解決。
  - **レビュー**：セキュリティや設計の観点でコードを見てもらう。
  - **計画分割**：大きな機能を小さなタスクに分けてもらう。
- **進め方のコツ**：1フェーズ＝1つの達成。**最初の感動（Phase 1：タップでアプリ起動）に最短で到達**してモチベーションを作る。

## 15. 学習ロードマップ（学ぶ順番）

未経験から無理なく進める順番。**①〜⑫を順にこなせば MVP に届く**。

1. **ターミナルの基本**（`ipconfig` でPCのIPを調べる、ファイアウォールの「許可」を理解）
2. **Node.js + npm** の導入（`node -v` / `npm -v` で確認、`npm install` の意味）
3. **Express** で「Hello」を返すだけのサーバーを動かす
4. **fetch** でスマホのボタン → サーバーに送る（HTTPの体験）
5. **child_process** でアプリを1つ起動する（最初の感動）
6. **`@nut-tree-fork/nut-js`** でショートカット送信
7. **NirCmd / win-audio** で音量・メディア操作
8. 設定を **`buttons.json`** に外出し（許可リスト化）
9. **PWA化**（manifest、`apple-touch-icon`、ホーム画面に追加）
10. **Vite + React** へUIを移行（綺麗なグリッド／アイコン）
11. **認証（PIN）** と **HTTPS** 化（service worker解禁）
12. **WebSocket** で状態表示

> **ネイティブビルドで詰まったら（重要メモ）**：`gyp ERR` / `Visual Studio not found` 等が出たら、(a) ライブラリが**プリビルド版**かを確認（nut.js は必ずフォーク）、(b) どうしても必要なら Node.js インストーラの「**Tools for Native Modules**」を入れる、(c) それでも難しければ**ビルド不要の代替**（音量は NirCmd など）に切り替える。

## 16. 制約・前提

- 端末は **Windows PC ＋ iPhone のみ**（**Macは無い**）。→ ネイティブiOSではなく **PWA** を採用。
- スマホとPCは **同じ Wi-Fi（LAN）** に接続している前提。
- 初回に **Windowsファイアウォールで「プライベートネットワークで許可」** を押す必要がある。
- **PCのIPアドレスは変わりうる**（DHCP）。→ 固定IP/DHCP予約を推奨。
- **サーバーは常駐**が必要（最初は「ターミナルを開いたままにする」。後で自動起動）。
- 開発者はアプリ開発**未経験**。→ 文書・技術選定は初心者向けを優先。

---

## 17. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| PCのIPが変わって繋がらない | 「昨日まで動いたのに」 | 固定IP/DHCP予約。将来 mDNS（.local）対応 |
| ネイティブビルドに失敗する | 環境構築で挫折 | **nut.js はフォークを使う**／プリビルド優先／音量は NirCmd で回避 |
| ネットワーク越しに勝手に操作される | 第三者の不正実行 | **許可リスト方式**＋LAN限定＋PIN/トークン＋値をシェルに直接渡さない |
| nut.js 公式の有料化に気づかず導入 | 課金・ビルド地獄 | `@nut-tree-fork/nut-js` を採用（本書に明記） |
| service worker が動かない | オフライン化できない | 当面はオンライン前提。Phase 4 でHTTPS化して解禁 |
| サーバーが落ちている | ボタンが無反応 | 自動起動（Phase 4）。エラー時はスマホに失敗を表示 |
| アプリのパスが間違っている | 起動しない | `buttons.json` にフルパス登録。エラーを分かりやすく返す |

## 18. 今後のロードマップ / フェーズ分け

各フェーズの終わりに**必ず「動く成果物」**がある状態にする。

- **Phase 0 — 環境構築**：Node.js LTS（「Tools for Native Modules」もチェック）/ Git / VS Code を導入。`ipconfig` でIP確認＋固定。リポジトリ初期化＋**この要件定義書をコミット**。
  - 完了の目安：環境が整い、文書がコミットされている。
- **Phase 1 — 1アプリ起動**：最小 Express ＋ `POST /api/press` で `child_process` から Chrome 起動。1ボタンのHTML。iPhone から `http://<IP>:3000` で起動成功。
  - 完了の目安：**スマホのタップでPCの Chrome が開く**（最初の感動）。
- **Phase 2 — アクション4種**：URL(`open`)・ショートカット(`@nut-tree-fork/nut-js`)・音量/メディア(NirCmd) を追加。`buttons.json` で許可リスト化。
  - 完了の目安：4種すべてが設定ファイル駆動で動く。
- **Phase 3 — UI刷新＆PWA化**：Vite + React に移行。設定からグリッド描画。SVGアイコン＋画像アップロード。manifest＋`apple-touch-icon`。ホーム画面に追加。
  - 完了の目安：**綺麗でインストール可能なUI**（アイコン品質という動機を実現）。
- **Phase 4 — 安全性・常駐・利便性**：PIN/トークン認証。自己署名HTTPS（service worker解禁）。プロファイル/ページ切替。Windows起動時に常駐。
  - 完了の目安：十分に安全で、常に使える、複数ページ対応。
- **Phase 5 — 拡張（任意）**：WebSocketで状態表示。ドラッグ&ドロップ編集。mDNS(.local)。新アクション種別（マクロ/OBS等）。
  - 完了の目安：単なるアプリから**拡張できる基盤**へ。
